# Лесной — день открытых дверей

Одностраничный лендинг на React и Express. Композиция вдохновлена референсом Ecoreel на Tilda: полноэкранная фотография, крупная типографика, свободные отступы, чередование светлых и тёмных секций. Палитра: молочный, песочный, графитовый и терракотовый. Объём создают тени, приподнятые карточки и наложение блоков.

## Запуск

Требуется Node.js 22 или новее.

```sh
npm install
npm run dev
```

Открыть http://localhost:3000. Express обслуживает и React, и API; отдельные порты и CORS не нужны. `npm run dev` собирает фронт и запускает сервер. Для изменения фронта во втором терминале запустите `npm run watch`, затем обновляйте страницу.

```sh
npm run build
npm start
```

`PORT`, `HOST`, `DATA_DIR` задаются переменными окружения. По умолчанию сервер слушает только `127.0.0.1:3000`. Для контейнера можно задать `HOST=0.0.0.0`. Для публикации нужен HTTPS через обратный прокси. Не запускайте несколько процессов сервера с одним каталогом NeDB.

## Заявки и база данных

Используется `@seald-io/nedb`, поддерживаемый Seald вариант NeDB: встроенная документная NoSQL БД с MongoDB-подобными запросами, индексами и очередью записи. Выбран для небольшого лендинга без отдельного сервера БД. В отличие от самостоятельной перезаписи JSON, хранением и конкурентными операциями управляет библиотека. Внутренний формат NeDB — журнал сериализованных документов на диске; это не бинарная БД. Если ожидается большой поток заявок или несколько экземпляров приложения, следует перейти на MongoDB с отдельным сервером/кластером. PouchDB с LevelDB тоже подходит, но добавляет ненужные здесь возможности репликации.

Заявки сохраняются в `data/registrations.db`. Каталог исключён из Git и не обслуживается Express. Не удаляйте его при перезапуске и резервируйте вместе с приложением. Для согласованной резервной копии остановите сервер перед копированием. База не шифруется библиотекой: используйте защищённый сервер и диск. Один телефон соответствует одной заявке; повторная отправка возвращает такой же ответ и не создаёт дубликат. Для нового мероприятия нужен новый каталог БД или изменение уникального ключа на мероприятие + телефон.

`POST /api/registrations` принимает имя, телефон, способ связи (`phone`, `telegram`, `whatsapp`), `consent: true` и пустое поле `website`. API нормализует телефон, проверяет типы и значения, сохраняет дату/версию согласия. Ответ об успехе отправляется только после записи. Есть лимит запросов, лимит размера тела, ловушка ботов и обработка ошибок. Список заявок доступен без авторизации через `/api/admin/registrations` и страницу `/admin`, как предусмотрено заданием. `GET /api/health` возвращает состояние запущенного приложения.

## Контент перед публикацией

Название «Лесной», дата, адрес и программа — демонстрационные. Замените данные в `src/content.js` и содержимое компонентов в `src/main.jsx`, добавьте настоящие контакты и имена спикеров. Фото — иллюстрации Unsplash, а не изображения реального посёлка. Карта не имитирует реальную локацию: сейчас показана фотография окружения с пометкой, что адрес уточняется. После получения координат добавьте маршрут и карту. Уберите `demo` только после замены данных. Уведомления менеджеру и автоматические звонки не подключены: сервер только сохраняет заявки.

Политика формы — демонстрационное описание. Для публичного приёма реальных персональных данных необходимо указать оператора, контакт для отзыва согласия, срок хранения и окончательную политику. Сейчас запись не означает регистрацию на реально организованное событие.

## Адаптивность и браузеры

Пять секций по ТЗ. Все основные CTA ведут к одной форме; вторичная ссылка открывает программу. Резиновая ширина контейнера с ограничением максимального размера; отдельные композиции для телефона, планшета и компьютера. Предусмотрены меню, клавиатурная навигация, состояния формы, диалог политики с управлением фокусом и уменьшение анимации по системной настройке.

Из-за упоминания Internet Explorer 11 в ТЗ используется React 17, Babel с целью IE11, ES5-вывод Webpack и `core-js`. Форма отправляется через совместимый XMLHttpRequest с таймаутом 15 секунд. CSS не зависит от Grid, CSS-переменных или flex-gap. В IE11 нет плавной прокрутки и некоторых косметических улучшений; полноценное визуальное тестирование IE11 требует Windows. Основная цель — актуальные Chrome, Safari, Firefox, Edge и Opera на PC/Mac. Подготовлены автоматизированные проверки через Chromium, WebKit и Firefox; это не заменяет ручную проверку каждой марки браузера и IE11.

## Проверки

```sh
npm test
npx playwright install chromium firefox webkit
npm run test:ui
```

API-проверки используют временную БД: валидация, параллельная запись одинаковых номеров, сохранение после открытия БД заново, ошибки записи, malformed/oversized JSON и ограничение запросов. DOM-тест загружает собранный React с настоящего Express, проверяет пять секций, ссылки CTA, меню, политику с фокусом и отправку формы в БД. DOM-тест не проверяет геометрию страницы. Браузерные UI-проверки проверяют изображения, отсутствие горизонтальной прокрутки на ширинах 320–1440 px, меню, политику и запись формы в БД. Снимки сохраняются в `artifacts/`. Тестовые заявки не попадают в рабочую БД.

В среде первоначальной разработки сборка и все три API/DOM-теста выполнены успешно. Работающий сервер вернул HTTP 200 для страницы и `status: ok` для health endpoint. Полноценная браузерная проверка пока не подтверждена: локальные браузеры аварийно завершались при запуске из-за системных ограничений среды macOS. Запустите `npm run test:ui` в обычном терминале после установки браузеров. Можно выбрать движки через `PLAYWRIGHT_ENGINES=chromium,firefox,webkit` и указать собственный путь через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` (аналогично для Firefox/WebKit).

Источники: [Tilda](https://testwebsiteforamir.tilda.ws/), [NeDB](https://github.com/seald/nedb), [React и IE](https://react.dev/blog/2022/03/08/react-18-upgrade-guide).

## Админка

Открыть http://localhost:3000/admin. Вход не требуется. Видны имя, телефон, способ связи, время создания, согласие и номер заявки. Новые заявки сверху; по 50 записей на страницу. Кнопка «Обновить» перечитывает БД. Время отображается в часовом поясе устройства. Админка только просматривает данные.
